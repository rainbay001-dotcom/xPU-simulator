1. 背景与动机

xPU-Simulator 目前仅建模纯文本 LLM 推理流程：embedding → N 层 Transformer → lm_head。多模态模型（LLaVA、Qwen2.5-VL、InternVL2.5、DeepSeek-VL2、Gemma3、Pixtral 等）在此流程前端增加了视觉编码器和投影器/连接器，将图像 Token 注入 LLM 序列。这从根本上改变了性能特征：

  • 视觉编码器是一个独立的 ViT 模型（300M–6B 参数），完全在 prefill 阶段运行，无 decode 阶段。在高分辨率场景下，FastVLM（Apple, CVPR 2025）研究表明视觉编码器耗时可超过 LLM prefill 时间 2 倍以上，成为 TTFT 的瓶颈。
  • 动态分辨率分块（InternVL、Qwen2.5-VL、LLaVA-NeXT）导致视觉 Token 数量从 ~256 到 ~13,000+ 不等，极大影响 LLM prefill 开销。
  • Token 压缩（Pixel Shuffle、空间合并、Perceiver Resampler）在视觉 Token 进入 LLM 前对其进行缩减——这是影响延迟的关键参数。
  • 多图和视频输入可将总 Token 数推至 50K+，使吞吐量估算与纯文本模型截然不同。
结论：如果不支持多模态仿真，模拟器将无法预测当前增长最快的一类生产模型的 TTFT。

2. 架构调研

2.1 VLM 整体结构

所有主流 VLM 可分解为三个阶段：

Image ──▶ 视觉编码器 ──▶ 投影器/连接器 ──▶ LLM 主干 ▲ Text ─────────────────────────────────────────────┘

计算图为顺序流水线：视觉编码器首先运行（或在独立设备上并行），其输出 Token 经投影后与文本 Embedding 拼接，完整序列进入 LLM。

O(P2 · d + P · d2)，其中 P = (H/p) × (W/p)

2.5 视觉 Token 融入 LLM 的方式

三种集成范式：

  1. 序列拼接（最主流）：视觉 Token 投影至 LLM 隐藏维度后与文本 Embedding 拼接：[BOS, <img_start>, v1, v2, ..., vN, <img_end>, t1, t2, ...]。统一序列上执行标准自注意力。LLaVA、InternVL、DeepSeek-VL2、Qwen2.5-VL、Pixtral、Gemma3 均采用此方式。
  2. Cross-Attention 注入：视觉 Token 不在序列中。在 LLM 的特定层（每 K 层）插入专用的交叉注意力层来访问视觉特征。Flamingo 和 Llama 3.2-Vision 采用此方式。需修改 LLM 层模板。
  3. 模态专家（CogVLM）：每个 LLM 层中为每种模态设置并行的 QKV + FFN。视觉 Token 使用视觉专家，文本 Token 使用文本专家。每层参数翻倍但保持模态分离。
设计启示：序列拼接作为默认方案 — 它只改变输入 LLM 的有效序列长度，现有仿真逻辑无需修改。Cross-Attention 和模态专家需要新的 LLM 层变体。

4. 方案设计

4.1 设计原则

  1. 复用，不复制：视觉编码器是标准 Transformer — 复用 GraphBuilder.gqa_attention、dense_ffn、norm 等。LLM 主干不变，仅有效序列长度增加。
  2. 配置驱动：沿用现有 normalize_config → ArchitectureHandler.build_layer 模式。新增 VisionConfig 数据类和 VLMHandler 基类。从 HF config.json 自动检测。
  3. 可组合：VLM Handler 包装现有 LLM Handler（如 StandardTransformerHandler）— 不复制 LLM 层逻辑。
  4. 分辨率感知：用户指定图像尺寸；Handler 根据模型的分辨率策略计算视觉 Token 数量。

4.2 新数据结构

VisionConfig 数据类（frontend/config_normalizer.py）

@dataclass
class VisionConfig:
    """视觉编码器配置，从 HF vision_config 归一化而来。"""
    encoder_type: str              # "clip", "siglip", "internvit", "custom"
    image_size: int                # 基础图像尺寸（如 336, 384, 448）
    patch_size: int                # Patch 尺寸（如 14, 16）
    hidden_size: int               # 视觉隐藏维度
    num_hidden_layers: int         # ViT 层数
    num_attention_heads: int       # ViT 注意力头数
    intermediate_size: int         # ViT FFN 中间维度
    hidden_act: str = "gelu"       # ViT 激活函数
    num_channels: int = 3          # 输入通道数（RGB）

    # 投影器
    projector_type: str = "mlp"    # "linear", "mlp", "qformer", "perceiver",
                                   # "cross_attn", "pixel_shuffle_mlp"
    projector_hidden_size: int | None = None
    projector_output_size: int | None = None
    spatial_merge_size: int = 1    # 每轴空间压缩因子（2 表示 2×2=4 Token → 1 Token）

    # 分辨率策略
    resolution_strategy: str = "fixed"  # "fixed", "anyres", "dynamic_tile", "native"
    max_tiles: int = 1
    use_thumbnail: bool = False
    tile_size: int | None = None
    image_grid_pinpoints: list[list[int]] | None = None

    # Perceiver / Q-Former 专用
    num_query_tokens: int = 32

    # 特征提取
    vision_feature_layer: int = -1  # 从 ViT 哪一层提取特征（-2 表示跳过最后一层）

    @property
    def patches_per_image(self) -> int:
        """单个 tile 在基础分辨率下的 Patch 数量。"""
        return (self.image_size // self.patch_size) ** 2

    @property
    def tokens_per_tile(self) -> int:
        """空间压缩后每个 tile 的视觉 Token 数。"""
        s = self.spatial_merge_size
        return self.patches_per_image // (s * s)

    def num_vision_tokens(self, img_w=0, img_h=0, num_tiles=1) -> int:
        """根据图像尺寸或 tile 数计算总视觉 Token 数。"""
        if self.resolution_strategy == "native" and img_w > 0 and img_h > 0:
            p = self.patch_size
            s = self.spatial_merge_size
            return (math.ceil(img_w/p) * math.ceil(img_h/p)) // (s * s)
        effective_tiles = num_tiles + (1 if self.use_thumbnail else 0)
        return effective_tiles * self.tokens_per_tile

4.3 视觉编码器图构建

在 GraphBuilder 中新增 vision_encoder 组合方法：

def vision_encoder(self, prefix: str, vcfg: VisionConfig,
                   num_patches: int, B: int = 1,
                   prev: Node | None = None) -> Node:
    """构建 ViT 视觉编码器子图。"""
    tokens = B * num_patches

    # 1. Patch Embedding：等效于线性投影
    #    [B*P, C*p*p] × [C*p*p, D_v]
    patch_dim = vcfg.num_channels * vcfg.patch_size * vcfg.patch_size
    node = self.matmul(f"{prefix}.patch_embed",
                       tokens, patch_dim, vcfg.hidden_size,
                       *([prev] if prev else []))

    # 2. ViT Transformer 层
    n_layers = vcfg.num_encoder_layers()
    for i in range(n_layers):
        lp = f"{prefix}.layer{i}"
        # Pre-Norm
        node = self.norm(f"{lp}.norm1", (tokens, vcfg.hidden_size), node)
        # 自注意力（ViT 使用标准 MHA，非 GQA/MLA）
        node = self.gqa_attention(
            f"{lp}.attn", tokens, B, num_patches,
            dim=vcfg.hidden_size,
            n_heads=vcfg.num_attention_heads,
            n_kv_heads=vcfg.num_attention_heads,  # MHA
            head_dim=vcfg.hidden_size // vcfg.num_attention_heads,
            rope=False,  # ViT 使用学习/绝对位置编码
            prev=node,
        )
        # FFN Pre-Norm
        node = self.norm(f"{lp}.norm2", (tokens, vcfg.hidden_size), node)
        # FFN
        act = OpType.GELU if vcfg.hidden_act in ("gelu", "quick_gelu") \
              else OpType.SILU
        node = self.dense_ffn(f"{lp}.ffn", tokens,
                              vcfg.hidden_size, vcfg.intermediate_size,
                              activation=act, prev=node)

    return node

4.4 投影器图构建

def vision_projector(self, prefix: str, vcfg: VisionConfig,
                     num_tokens: int, llm_hidden: int,
                     B: int = 1, prev: Node | None = None) -> Node:
    """构建视觉到 LLM 的投影器子图。"""
    tokens = B * num_tokens

    if vcfg.projector_type == "linear":
        return self.matmul(f"{prefix}.proj",
                           tokens, vcfg.hidden_size, llm_hidden, ...)

    elif vcfg.projector_type in ("mlp", "pixel_shuffle_mlp"):
        inter = vcfg.projector_hidden_size or vcfg.hidden_size
        in_dim = vcfg.hidden_size
        if vcfg.projector_type == "pixel_shuffle_mlp":
            in_dim = vcfg.hidden_size * vcfg.spatial_merge_size ** 2
        node = self.matmul(f"{prefix}.proj_fc1", tokens, in_dim, inter, ...)
        node = self.elementwise(f"{prefix}.proj_act",
                                (tokens, inter), OpType.GELU, node)
        node = self.matmul(f"{prefix}.proj_fc2", tokens, inter, llm_hidden, node)
        return node

    elif vcfg.projector_type == "qformer":
        # Q-Former：固定输出 num_query_tokens 个 Token
        q_tokens = B * vcfg.num_query_tokens
        node = self.matmul(f"{prefix}.qformer_cross",
                           q_tokens, vcfg.hidden_size, llm_hidden, ...)
        return node

    elif vcfg.projector_type == "perceiver":
        q_tokens = B * vcfg.num_query_tokens
        node = self.matmul(f"{prefix}.perceiver_proj",
                           q_tokens, vcfg.hidden_size, llm_hidden, ...)
        return node
    # ... 回退为线性投影

4.5 VLM 架构 Handler

基类 VLMHandler

class VLMHandler(ArchitectureHandler):
    """视觉-语言模型的基础 Handler。
    包装现有 LLM Handler，在前端添加视觉编码器 + 投影器。
    子类只需重写分辨率/分块逻辑。"""

    def __init__(self, llm_handler: ArchitectureHandler):
        self.llm_handler = llm_handler

    def build_vision_stage(self, builder, cfg, mm_input, B):
        """构建视觉编码器 + 投影器。
        返回 (last_node, num_vision_tokens)。"""
        vcfg = cfg.vision_config
        total_vision_tokens = 0

        last_node = None
        for i, img in enumerate(mm_input.images):
            num_patches = self._compute_patches(vcfg, img)
            enc_node = builder.vision_encoder(
                f"vision.img{i}", vcfg, num_patches, B, last_node)

            # 空间压缩后的 Token 数
            if vcfg.projector_type == "pixel_shuffle_mlp":
                proj_tokens = num_patches // (vcfg.spatial_merge_size ** 2)
            elif vcfg.projector_type in ("qformer", "perceiver"):
                proj_tokens = vcfg.num_query_tokens
            else:
                proj_tokens = num_patches

            last_node = builder.vision_projector(
                f"vision.img{i}", vcfg, proj_tokens,
                cfg.hidden_size, B, enc_node)
            total_vision_tokens += proj_tokens

        return last_node, total_vision_tokens

5. 算力模型分析

5.1 视觉编码器开销

视觉编码器是标准的 ViT — 其算子（MATMUL、LAYER_NORM、SOFTMAX、GELU）已被现有 GPU 和 NPU 算力模型支持。无需新增算子类型。

关键开销特征：

  • Patch Embedding：一次 MATMUL，形状为 [B*P, C*p*p] × [C*p*p, D_v]。336px/p=14 时：[576, 588] × [588, 1024] — 较小，访存瓶颈。
  • ViT 自注意力：[B*H, P, P] 注意力矩阵。336px 时 P=576，可控。896px + 4 块时 P=4096+，因二次增长成为瓶颈。
  • ViT FFN：[B*P, D_v] × [D_v, 4*D_v] — 标准 MATMUL，大 P 时为计算瓶颈。

5.2 Prefill 序列长度

对于包含长度为 T 的文本提示和 N 张图像（共产生 V 个视觉 Token）的 VLM 请求：

effective_prefill_seq = V + T

这就是送入 LLM 主干的序列长度。模拟器可直接使用此值 — 对于序列拼接模型，LLM 代码无需任何修改。

5.3 TTFT 分解

TTFT = 视觉编码器时间 + 投影器时间 + LLM prefill 时间(V + T)

HTML 报告应展示此分解。视觉编码器和投影器仅在 prefill 阶段运行 — 不参与 decode。

5.4 Decode 阶段

对于序列拼接模型，Decode 不变：每步仅生成一个新文本 Token，对完整 KV Cache（包含缓存的视觉 Token KV）执行注意力。KV Cache 大小增加了 V 个条目，影响内存但不影响每 Token 的 decode 延迟（超出已建模的 KV 注意力开销之外）。

5.5 多图与视频

对于 N 张图像，Token 数分别为 V1, V2, ..., VN：

total_vision_tokens = ∑ Vi
effective_prefill_seq = ∑ Vi + T

视频建模为图像帧序列，可选时间压缩（如 Qwen2.5-VL 的 temporal_patch_size=2 将帧数减半）。

6. Cross-Attention 模型（第二阶段）

对于 Llama 3.2-Vision 等模型，视觉 Token 不拼接到序列中，而是通过特定 LLM 层中的交叉注意力访问：

  • 在 VisionConfig 中新增 cross_attn_layer_indices 字段（例如每 4 层插入一次）。
  • 修改 LLM Handler 的 build_layer，条件性地插入交叉注意力块：cross_attn(Q=文本Token, KV=视觉Token)。
  • 交叉注意力的 MATMUL 形状为 [B*H, T, V]（QK）和 [B*H, T, D]（输出）— 不同于自注意力的 [B*H, T, T]。

这是对 build_layer 的局部扩展，不影响流水线其余部分。

7. 实施计划

Phase 1 核心 VLM 支持（序列拼接）

步骤涉及文件描述

8. API 使用示例

基础 VLM 仿真

from xpu_simulator import ConfigExtractor, MultiModalInput, ImageInput

ext = ConfigExtractor()
graph = ext.extract(
    "path/to/llava-next-config.json",
    batch_size=1,
    seq_len=128,  # 文本 Token 数
    mm_input=MultiModalInput(
        num_text_tokens=128,
        images=[ImageInput(width=672, height=672, num_tiles=4)],
    ),
)
# 计算图包含：视觉编码器 (CLIP ViT-L, 4 tiles) +
#              MLP 投影器 +
#              LLM prefill (4×576 + 128) Token

视觉编码器 vs LLM Prefill 开销对比

from xpu_simulator import PerformanceEvaluator
from xpu_simulator.backends.gpu import GPUCostModel, gpu_specs

cost = GPUCostModel(gpu_specs["H100"])
evaluator = PerformanceEvaluator(cost)
result = evaluator.run(graph, overlap=True)

# 按类别分解
for cat, us in result.category_latency.items():
    print(f"{cat}: {us:.0f} us")
# Vision Encoder: 1234 us
# Vision Projector: 12 us
# Attention Projections: 5678 us
# ...

分辨率扫描

# 扫描图像分辨率以寻找 TTFT 与质量的权衡
for tiles in [1, 4, 9, 12]:
    graph = ext.extract(config, batch_size=1, seq_len=128,
                        mm_input=MultiModalInput(
                            images=[ImageInput(num_tiles=tiles)]))
    result = evaluator.run(graph, overlap=True)
