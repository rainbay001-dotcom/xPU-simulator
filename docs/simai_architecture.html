SimAI Architecture

Full-Stack Distributed AI Training & Inference Simulator
Alibaba Cloud · NSDI’25 · aliyun/SimAI

Overview

SimAI is a full-stack, high-precision simulator for large-scale LLM training and inference. It models the entire distributed AI stack: from training framework orchestration and computation kernels, through collective communication library behavior, down to packet-level network transport.

The motivation is pragmatic: GPU clusters cost millions to procure, and most capacity runs production workloads. Before deploying a new network topology, parallelism strategy, or hardware generation, teams need to evaluate performance via simulation. SimAI achieves 98.1% average alignment with real-world training results across diverse scenarios.

Five Components SimAI is composed of five independently-developed subsystems wired together: AICB workload generation → astra-sim framework simulation → SimCCL collective decomposition → ns-3 network simulation → Vidur inference scheduling.

1. AICB — AI Communication Benchmark

AICB (aliyun/aicb) is SimAI’s workload generation layer. Unlike generic network benchmarks (nccl-tests, perftest), AICB generates communication workloads with precise patterns aligned to actual model training: the exact sequence, type, and data size of every collective operation that occurs during a training iteration.

AIOB — AI Operation Benchmark

AIOB is embedded within AICB and profiles computation kernels on target GPUs to obtain real execution times. SimAI supports three computation time sources:

  1. AIOB profiling — run kernels on target GPU, measure wallclock
  2. Parameter extrapolation — TXPU = α × TA100 where α = f(kernel_type, FLOPS_ratio, BW_ratio)
  3. GPU simulator — GPGPU-Sim for unknown hardware microarchitectures

2. Astra-sim — Framework Layer

Astra-sim originated at Georgia Tech / Meta / Intel (ISPASS 2020, 2023). SimAI extends the 1.0 branch (astra-sim/astra-sim/tree/ASTRA-sim-1.0) with substantial modifications including MockNccl integration, fast-backend acceleration, and RDMA physical network support.

3. SimCCL — Collective Communication Library Simulator

SimCCL (aliyun/SimCCL) decomposes high-level collective operations into sets of point-to-point (P2P) Send/Recv operations, faithfully reproducing NCCL’s behavior without requiring GPUs. Only 572 lines from the NCCL codebase are essential — algorithm selection, chunking, and channel assignment logic.

Algorithms & Protocols

Figure 6 — NCCL algorithm × protocol matrix modeled by SimCCL. Each cell has hardware-specific latency/bandwidth constants.

P2P Decomposition Flow

The core decomposition happens in MockNcclGroup::genFlowModels(). It takes a collective specification and produces a map of SingleFlow objects — each representing one P2P transfer with explicit dependencies: 

struct SingleFlow {
  int flow_id;                    // Unique flow identifier
  int src, dest;                  // Source and destination ranks
  uint64_t flow_size;             // Data size for this flow
  vector<int> parent_flow_id;     // Flows that must complete first
  vector<int> child_flow_id;      // Flows dependent on this one
  int channel_id;                 // Which channel (for multi-channel)
  int chunk_id;                   // Which chunk (for pipelining)
  string conn_type;               // "RING", "PXN_INIT", etc.
};

Figure 7 — Ring AllReduce decomposed into P2P flows: 3 Reduce-Scatter steps + 3 AllGather steps for 4 ranks.

Bus Bandwidth Calculation

calbusbw.cc computes effective bus bandwidth for each algorithm, factoring in hardware topology:

GPUNVLink BWPCIe BWNIC BWNVLS BW

The effective bus bandwidth is computed as:

Ring:  busbw = min(nvlink_bw, nic_bw × nics_per_node) × (N-1)/N
Tree:  busbw = min(nvlink_bw/2, nic_bw × nics) × (N-1)/N  [with correction factors]
NVLS:  busbw = nvls_bw × gpus / (gpus-1)                      [H100/H800 only]
Best:  max(ring, tree, nvls)

5. Vidur — Inference Simulation

Vidur (originally from Microsoft Research, MLSys 2024) is an LLM inference simulator. Alibaba’s fork (vidur-alibabacloud) adds SimAI-backed communication time prediction, prefill/decode disaggregation (inspired by Splitwise), and MoE model support.

The Simulator class uses a min-heap priority queue. Events are processed in time order:

Prefill/Decode Disaggregation

Inspired by the Splitwise approach, Alibaba’s Vidur fork supports disaggregated prefill and decode pools. Prefill-heavy requests run on dedicated nodes; after prefill completes, the KV cache is transferred to a decode node via point-to-point communication:

Figure 11 — Disaggregated serving: separate compute-optimized prefill pool and memory-optimized decode pool with KV cache transfer.

SimAI Integration

The key integration is in sklearn_execution_time_predictor.py. The TPTimePredictor class generates AICB workload files (SimAIWorkload) and invokes the SimAI binary as a subprocess:

  1. Vidur creates a SimAIWorkload with model dimensions and batch parameters
  2. Workload is written to a temp file; a content hash caches results
  3. SimAI binary (SimAI_analytical or SimAI_simulator) is spawned
  4. CSV output is parsed back into execution time estimates
  5. Results feed into Vidur’s event-driven scheduler

Supported backends: aicb (direct AICB call), simai_analytical (busbw-based), simai_simulation (full ns-3 packet simulation).

End-to-End Data Flow

Training Simulation Flow

  1. User specifies configuration
    Model parameters (hidden_size, num_layers, etc.), parallelism strategy (TP, DP, PP, EP sizes), cluster topology (GPU type, network bandwidth, switch layout).
  2. AICB generates workload
    Extracts communication patterns from model + parallelism config. Profiles compute kernels via AIOB. Outputs workload.txt with layer-by-layer compute times, collective types, and data sizes.
  3. Astra-sim loads workload
    Creates one Sys instance per GPU rank. Workload class parses the workload file, creates Layer objects. Begins event-driven iteration: Forward → Input Gradient → Weight Gradient.
  4. SimCCL decomposes collectives
    When a collective operation is encountered, MockNcclGroup::genFlowModels() selects the optimal algorithm/protocol and decomposes it into P2P SingleFlow objects with explicit dependency DAGs. Multi-channel pipelining splits data across parallel channels.
  5. Network backend processes P2P flows
    Analytical mode: looks up bus bandwidth → instant time estimate.
    Simulation mode: injects packets into ns-3 → models congestion, ECMP, PFC, DCQCN.
    Physical mode: sends real RDMA traffic via InfiniBand verbs.
  6. Results collected
    Per-layer timing breakdown, total iteration time, compute vs. communication vs. exposed communication, bubble fraction, CSV output for analysis.

Inference Simulation Flow

  1. Vidur generates requests
    RequestGenerator creates inference requests with Poisson or trace-driven arrival patterns. Each request has a prompt length and expected generation length.
  2. Global scheduler dispatches
    GlobalScheduler (FCFS, Splitwise, etc.) assigns requests to replicas based on load.
  3. Replica forms batches
    ReplicaScheduler groups requests into batches. For disaggregated mode, prefill and decode batches go to separate pools.
  4. Execution time prediction
    ExecutionTimePredictor calls SimAI (analytical or simulation) to estimate prefill time, decode time, and TP communication overhead for each batch.
  5. Metrics recorded
    TTFT (Time to First Token), TBT (Time Between Tokens), end-to-end latency, throughput, scheduling delay. Output as JSON trace, Chrome trace, CSV.

Key Design Decisions

1. Selective High-Fidelity Integration Rather than simulating everything at the lowest level, SimAI integrates only the parts that matter for accuracy. Only 572 lines from NCCL’s codebase are essential — the algorithm selection, chunking, and channel assignment logic. GPU kernel code, driver interactions, and CUDA runtime are abstracted away.
2. Lock-Free Multi-Thread Acceleration SimAI uses std::atomic<bool> Sys::g_sys_inCriticalSection for lock-free global context sharing across threads. Each GPU rank runs in its own thread; the atomic flag serializes only critical sections. This achieves a 23× speedup over single-threaded execution.
3. Three-Mode Flexibility The same workload can be evaluated at three fidelity levels without modification. Analytical mode for rapid exploration (seconds), simulation mode for detailed analysis (minutes to hours), physical mode for ground-truth validation. Users iterate: analytical → simulation → physical.
4. Modular Composition over Monolith Each component (AICB, astra-sim, SimCCL, ns-3, Vidur) is a standalone project with its own repo, build system, and test suite. SimAI wires them together via well-defined interfaces: workload files (AICB → astra-sim), AstraNetworkAPI (astra-sim → ns-3), subprocess calls (Vidur → SimAI binary). This enables independent evolution and replacement.
5. Topology-Aware Communication SimCCL’s MockNcclGroup distinguishes NVLink (PATH_NVL), PCI (PATH_PIX/PXB), and network (PATH_NET) paths with hardware-specific latency/bandwidth tables. Algorithm selection automatically adapts to whether communication is intra-node or inter-node, matching real NCCL behavior.
6. PXN (Path-to-NIC) Optimization For multi-node ring collectives, SimCCL models NCCL’s PXN optimization: intra-node data is first gathered to the GPU closest to the NIC via NVLink, then sent across the network. This avoids PCIe/QPI bottlenecks and is critical for accurate inter-node bandwidth modeling.
7. Inference via Training Simulator Vidur reuses the training simulator for communication time prediction rather than building a separate comm model. This ensures inference TP communication estimates match training-validated accuracy. The integration is lightweight: subprocess call with cached results by content hash.
